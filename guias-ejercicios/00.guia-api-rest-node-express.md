# Guía práctica: Primera API REST con Node.js y Express

## Catálogo de libros con persistencia en memoria

---

## Objetivos de aprendizaje

Con esta guía buscamos que el estudiante logre:

- Explicar qué es un endpoint y cómo se estructura una URL de API.
- Diferenciar y utilizar parámetros de ruta (path params) y parámetros de consulta (query params).
- Implementar los métodos HTTP GET, POST, PUT y DELETE siguiendo el enfoque REST.
- Configurar variables de entorno para evitar valores fijos (hardcodeados) en el código.
- Aplicar buenas prácticas básicas: códigos de estado HTTP correctos, validación de entrada y respuestas consistentes.
- Probar una API con herramientas como curl o un cliente REST.

---

node --version

- Conocimientos básicos de JavaScript (funciones, objetos, arreglos).

## 2. Estructura del proyecto

```
catalogo-libros-api/
├── src/
│   ├── data/
│   │   └── libros.js
│   ├── routes/
│   │   └── libros.routes.js
│   └── server.js
├── .env
├── .env.example
├── .gitignore
├── package.json
```

Esta organización no es arbitraria: separamos `data`, `routes` y `server.js` porque más adelante, cuando cambiemos el arreglo en memoria por una base de datos, no vamos a tener que tocar la lógica de las rutas. `data/` guarda lo que hoy simula nuestra base de datos; `routes/` guarda la definición de los endpoints; `server.js` es el punto de entrada, donde se arma todo. `.env` guarda la configuración real del proyecto y no se sube al repositorio; `.env.example` sí se sube, y sirve para que cualquier compañero sepa qué variables necesita configurar antes de correr el proyecto.

---

## 3. Inicialización del proyecto

```bash
mkdir catalogo-libros-api
cd catalogo-libros-api
npm init -y
```

`npm init -y` genera el `package.json` con valores por defecto, sin preguntarnos nada. Ahí queda registrado el proyecto y, más adelante, sus dependencias.

### Instalación de dependencias

```bash
npm install express dotenv
npm install --save-dev nodemon
```

- **express**: el framework que vamos a usar durante todo el curso para construir APIs en Node.js. Nos simplifica el manejo de rutas y peticiones sin tener que trabajar directamente con el módulo nativo `http`.
- **dotenv**: nos permite leer el archivo `.env` y cargar esos valores en `process.env`. Sin esto, tendríamos que escribir cosas como el puerto directamente en el código, lo cual no es buena práctica.
- **nodemon** (como dependencia de desarrollo): reinicia el servidor automáticamente cada vez que guardamos un cambio. Sin esto, tocaría detener y volver a levantar el servidor manualmente cada vez.

Agreguen estos scripts en `package.json`:

```json
"scripts": {
  "start": "node src/server.js",
  "dev": "nodemon src/server.js"
}
```

`npm start` es para correr el servidor en modo normal; `npm run dev` es el que vamos a usar mientras desarrollamos, porque reinicia solo.

## 5. Datos en memoria

Archivo `src/data/libros.js`:

```javascript
// Arreglo en memoria que simula una base de datos.
// Los datos se pierden cada vez que el servidor se reinicia.
// Más adelante en el curso lo reemplazaremos por persistencia real.

let libros = [
  {
    id: 1,
    titulo: "Cien años de soledad",
    autor: "Gabriel García Márquez",
    genero: "novela",
    disponible: true
  },
  {
    id: 2,
    titulo: "El principito",
    autor: "Antoine de Saint-Exupéry",
    genero: "fábula",
    disponible: true
  },
  {
    id: 3,
    titulo: "1984",
    autor: "George Orwell",
    genero: "distopía",
    disponible: false
  }
];

module.exports = libros;
```

Exportamos el arreglo con `module.exports` para poder importarlo y manipularlo desde el archivo de rutas. Como es un arreglo en memoria, cualquier endpoint que lo modifique (crear, actualizar, eliminar) va a estar trabajando sobre esta misma referencia mientras el servidor siga corriendo. Apenas lo reinicien, vuelve a los tres libros de ejemplo.

## 6. Definición de rutas y endpoints

Archivo `src/routes/libros.routes.js`:

```javascript
const express = require("express");
const router = express.Router();
const libros = require("../data/libros");

// Variable auxiliar para generar nuevos identificadores.
let siguienteId = 4;

// ------------------------------------------------------------
// GET /libros
// Lista todos los libros. Admite parámetros de consulta (query params)
// opcionales para filtrar resultados: autor, genero, disponible.
// Ejemplo: GET /libros?autor=Orwell&disponible=true
// ------------------------------------------------------------
router.get("/", (req, res) => {
  const { autor, genero, disponible } = req.query;
  let resultado = libros;

  if (autor) {
    resultado = resultado.filter((libro) =>
      libro.autor.toLowerCase().includes(autor.toLowerCase())
    );
  }

  if (genero) {
    resultado = resultado.filter(
      (libro) => libro.genero.toLowerCase() === genero.toLowerCase()
    );
  }

  if (disponible !== undefined) {
    const esDisponible = disponible === "true";
    resultado = resultado.filter((libro) => libro.disponible === esDisponible);
  }

  res.status(200).json(resultado);
});

// ------------------------------------------------------------
// GET /libros/:id
// Obtiene un libro específico mediante un parámetro de ruta (path param).
// Ejemplo: GET /libros/2
// ------------------------------------------------------------
router.get("/:id", (req, res) => {
  const id = Number(req.params.id);
  const libro = libros.find((libro) => libro.id === id);

  if (!libro) {
    return res.status(404).json({ mensaje: "Libro no encontrado" });
  }

  res.status(200).json(libro);
});

// ------------------------------------------------------------
// POST /libros
// Crea un nuevo libro a partir del cuerpo (body) de la petición.
// ------------------------------------------------------------
router.post("/", (req, res) => {
  const { titulo, autor, genero, disponible } = req.body;

  if (!titulo || !autor) {
    return res
      .status(400)
      .json({ mensaje: "Los campos 'titulo' y 'autor' son obligatorios" });
  }

  const nuevoLibro = {
    id: siguienteId++,
    titulo,
    autor,
    genero: genero || "sin clasificar",
    disponible: disponible !== undefined ? disponible : true
  };

  libros.push(nuevoLibro);
  res.status(201).json(nuevoLibro);
});

// ------------------------------------------------------------
// PUT /libros/:id
// Actualiza un libro existente identificado por su id.
// ------------------------------------------------------------
router.put("/:id", (req, res) => {
  const id = Number(req.params.id);
  const libro = libros.find((libro) => libro.id === id);

  if (!libro) {
    return res.status(404).json({ mensaje: "Libro no encontrado" });
  }

  const { titulo, autor, genero, disponible } = req.body;

  if (titulo !== undefined) libro.titulo = titulo;
  if (autor !== undefined) libro.autor = autor;
  if (genero !== undefined) libro.genero = genero;
  if (disponible !== undefined) libro.disponible = disponible;

  res.status(200).json(libro);
});

// ------------------------------------------------------------
// DELETE /libros/:id
// Elimina un libro identificado por su id.
// ------------------------------------------------------------
router.delete("/:id", (req, res) => {
  const id = Number(req.params.id);
  const indice = libros.findIndex((libro) => libro.id === id);

  if (indice === -1) {
    return res.status(404).json({ mensaje: "Libro no encontrado" });
  }

  libros.splice(indice, 1);
  res.status(204).send();
});

module.exports = router;
```

**Puntos clave**

- El parámetro de ruta (`req.params`) identifica un recurso específico dentro de la URL, como en `/libros/2`. Lo usamos cuando ese valor forma parte de la identidad misma del recurso.
- El parámetro de consulta (`req.query`) sirve para filtrar, ordenar o paginar resultados, como en `/libros?autor=Orwell`. Es opcional y no identifica un recurso único; ajusta cómo se ve una colección.
- Los códigos de estado que usamos aquí: `200 OK` cuando todo sale bien y devolvemos contenido; `201 Created` al crear un recurso nuevo; `204 No Content` cuando la operación fue exitosa pero no hay nada que devolver (típico en DELETE); `400 Bad Request` cuando el cliente envía datos inválidos o incompletos; `404 Not Found` cuando el recurso no existe.

## 7. Configuración del servidor

Archivo `src/server.js`:

```javascript
require("dotenv").config();
const express = require("express");
const librosRoutes = require("./routes/libros.routes");

const app = express();
const PORT = process.env.PORT || 3000;

// Middleware para interpretar cuerpos de petición en formato JSON.
app.use(express.json());

// Se conecta el conjunto de rutas de libros bajo el prefijo /libros.
app.use("/libros", librosRoutes);

// Ruta raíz de verificación (health check).
app.get("/", (req, res) => {
  res.status(200).json({ mensaje: "API de catálogo de libros activa" });
});

app.listen(PORT, () => {
  console.log(`Servidor escuchando en el puerto ${PORT}`);
});
```

Aquí pasan tres cosas que vale la pena resaltar en clase. Primero, `require("dotenv").config()` tiene que ejecutarse antes de que cualquier otra parte del código intente leer `process.env`, por eso va de primeras. Segundo, `express.json()` es el middleware que le permite a Express entender cuerpos de petición en JSON; sin esto, `req.body` llegaría vacío en los POST y PUT. Y tercero, `process.env.PORT || 3000` usa el puerto definido en la variable de entorno, pero si por alguna razón no existe, cae en 3000 como valor por defecto.

## 9. Pruebas de los endpoints con curl

```bash
# Listar todos los libros
curl http://localhost:3000/libros

# Filtrar por autor (query param)
curl "http://localhost:3000/libros?autor=Orwell"

# Filtrar por disponibilidad (query param)
curl "http://localhost:3000/libros?disponible=true"

# Obtener un libro por id (path param)
curl http://localhost:3000/libros/1

# Crear un nuevo libro
curl -X POST http://localhost:3000/libros \
  -H "Content-Type: application/json" \
  -d '{"titulo":"Rayuela","autor":"Julio Cortázar","genero":"novela"}'

# Actualizar un libro existente
curl -X PUT http://localhost:3000/libros/2 \
  -H "Content-Type: application/json" \
  -d '{"disponible":false}'

# Eliminar un libro
curl -X DELETE http://localhost:3000/libros/3
```

Si alguien prefiere una interfaz gráfica en lugar de la terminal, Postman o la extensión Thunder Client de VS Code funcionan igual de bien para estas pruebas.

## 10. Buenas prácticas aplicadas en esta guía

- Separación de responsabilidades: datos, rutas y configuración del servidor en archivos distintos.
- Uso de variables de entorno en lugar de valores fijos en el código.
- Validación básica de datos de entrada antes de procesarlos.
- Uso correcto y consistente de códigos de estado HTTP.
- Respuestas siempre en formato JSON, con estructura predecible.
- Nombres de recursos en plural (`/libros`), siguiendo la convención REST.
